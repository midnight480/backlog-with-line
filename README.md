# backlog-with-line

LINE グループに常設する Bot。メンション付きでメモを送ると、Backlog への新規起票または既存課題へのコメントを作成する。起票内容の整形は AWS Bedrock 上の **xAI Grok 4.6**（`us.xai.grok-4.6`）が担当し、生成物の末尾には `Generated by AWS Bedrock (Grok 4.6)` を付与する。

## アーキテクチャ

```
LINE group ──Webhook──▶ Lambda (Function URL) ──▶ Backlog REST API
                             │
Backlog ──Webhook──▶ /webhook/backlog/:token    ├──▶ Bedrock Converse API (Grok 4.6, us-west-2)
                             │                  ├──▶ DynamoDB（設定・保留アクション・紐付け・冪等化）
LIFF(管理画面) ◀──/admin─────┘                  └──▶ SSM Parameter Store（シークレット）
```

- **Lambda + Function URL**：`AUTH_TYPE=NONE` の公開エンドポイント。入り口で `X-Line-Signature`（HMAC-SHA256 + チャネルシークレット）を検証し、不一致は 401 で即破棄
- **DynamoDB**（シングルテーブル・TTL 付き）：`GROUP#` 設定 / `PENDING#` 確認待ち / `AWAIT#` 入力待ち / `MSG#` メッセージ→課題紐付け / `SEEN#` 冪等化 / `WBTOKEN#` Webhook トークン逆引き
- **SSM Parameter Store**：LINE チャネル情報と Backlog API キー（SecureString + KMS 暗号化）
- **LIFF**：グループ ↔ プロジェクト紐付け設定画面と起票フォーム（`liff.getContext()` で groupId を取得）

## 使い方

```
@bot ランチ会の日程を来週中に決めたい
  → [新規起票] [既存課題にコメント] [キャンセル]

新規起票 → Grok 4.6 が下書き生成 → プレビュー確認
  → [この内容で起票] / [フォームで修正(LIFF)] → 起票結果を返信

既存課題にコメント → 「課題番号を入力」（例: 123 → SAGA-123）
  → 確認 → コメント投稿

ボットの起票/通知メッセージに「返信」→ その課題へ直接コメント追記
Backlog でコメント → グループへプッシュ通知（APIキー所有者自身のコメントは通知しない）
```

## 全発言ミラー

管理画面で有効化すると、グループ内の**全メッセージ**を Backlog 課題のコメントとして記録する（メンション不要）。

- **流し先**：「週次ログ課題に記録」（`LINEログ 2026-10-05週` のような課題を週ごとに自動起票）または「固定課題に記録」
- **記録形式**：`YYYY/MM/DD HH:mm 表示名` + 本文。画像・スタンプ等は `[画像]` のようなプレースホルダ
- **お知らせ**：ミラー先ユーザーを指定すると `notifiedUserId[]` 付きでコメントが投稿され、Backlogの「お知らせ」が届く → 「LINEに何か来た」と気づける
- APIキー所有者の投稿なので Backlog→LINE の通知ループは発生しない
- **推奨運用**：Backlog に「LINE通知bot」専用ユーザーを作成してプロジェクトに参加させ、そのAPIキーを使う（発言者と区別でき、お知らせ通知も正しく届く）
- **注意**：全発言が外部サービスに記録されるため、グループメンバーへの告知・合意を取ること

## セットアップ

詳細手順は **[docs/SETUP-LINE.md](docs/SETUP-LINE.md)** を参照（LINE Notifyは2025-03-31に終了済み。本構成は後継のMessaging APIを使用）。

概要：

1. LINE Developersコンソールで Messaging API チャネル作成（グループ参加許可をON・トークン発行）
2. LIFF アプリ追加（スコープ `openid` 必須、エンドポイントは仮URLでOK）
3. AWS：Bedrock で Grok 4.6 を有効化（us-west-2）→ SSM に4パラメータ登録 → `cdk deploy`
4. コンソールに戻り Webhook URL・LIFF エンドポイントを本物の Function URL に更新
5. ボットを友だち追加 → グループ招待 → LIFF設定画面でBacklog紐付け → Webhook URLをBacklogへ登録

## コスト・制限メモ

- **応答メッセージ（reply）は通数カウント外・無料**。確認ボタンや結果返信はすべて reply
- **プッシュはカウント対象**：Backlog→LINE 通知と LIFF 起票結果通知が該当。コミュニケーションプラン（無料）は月200通
- Grok 4.6 の呼び出しは「新規起票」選択時のみ（約 $2.20/$6.60 per 1M tokens・AWS請求なのでAWSクレジット対象）
- 確認待ちアクションの有効期限は10分（TTL）。メッセージ→課題の紐付けは30日
- 課題指定は番号のみでOK（プロジェクトキーは設定済みのものと自動結合）
